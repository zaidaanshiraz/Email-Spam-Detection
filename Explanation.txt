GuardianMail is an advanced, AI-powered email security application designed to protect users from the growing threat of phishing attacks and malicious online content. Traditional email clients rely on basic filters that are often bypassed by sophisticated social engineering tactics. GuardianMail addresses this gap by leveraging a state-of-the-art, transformer-driven NLP (Natural Language Processing) framework to perform deep analysis of email content, sender reputation, and embedded links in real-time.

The project goes beyond simple detection by creating a comprehensive security-first email experience. It not only identifies and flags potential threats with high precision but also educates the user through interactive tools like an AI Security Coach and provides intelligent assistance for composing safe replies. The result is a smart, proactive email client that acts as a personal cybersecurity analyst for every user.

The application is built on a modern, robust, and scalable technology stack, prioritizing performance, developer experience, and seamless AI integration.

Frontend Framework: Next.js (with React) using the App Router for a fast, server-rendered user interface.
UI Components: ShadCN UI and Tailwind CSS for a clean, professional, and responsive design system. Icons are provided by the Lucide React library.
Artificial Intelligence: Google Genkit is the core AI orchestration framework used to define, run, and manage all generative AI flows. This connects to Google's powerful Gemini family of models for all AI tasks.
Backend & Authentication: Firebase provides the backend infrastructure, including:
Firebase Authentication for secure user login and registration.
Cloud Firestore as the NoSQL database for storing user settings and other application data (though currently emulated with localStorage for a simplified multi-user experience).
Programming Language: TypeScript is used throughout the project for enhanced code quality, type safety, and maintainability.
Styling and Design: The visual identity is defined by a specific color palette (Deep Blue, Teal, Light Gray) and modern typography ('Inter' and 'Space Grotesk' fonts), all implemented using Tailwind CSS and CSS variables.
The primary objectives of the GuardianMail project are:

High-Precision Phishing Detection: To develop and implement an AI model capable of accurately identifying phishing emails by analyzing content, language, sender details, and technical indicators.
Proactive Threat Prevention: To automatically scan and assess the risk of all embedded URLs within an email before the user interacts with them, providing immediate visual warnings.
Enhance User Security Awareness: To empower users with tools that not only protect them but also educate them about cybersecurity threats, such as the AI Security Coach.
Reduce Human Error: To minimize the risk of accidental engagement with malicious content by providing AI-assisted tools for composing safe and context-aware replies.
Develop a Modern & Usable Interface: To create a fully-featured, intuitive, and aesthetically pleasing email client that integrates these advanced security features seamlessly into the daily workflow.
GuardianMail is designed as a multi-layered system that combines a functional email client with a powerful AI security engine.

Real-time Email Analysis: As emails arrive in the inbox, the system automatically triggers an AI flow (detectPhishingEmail) that analyzes multiple factors:
Content Analysis: Scrutinizes the email body and subject for urgency, threats, and suspicious language.
Sender Analysis: Evaluates the sender's domain and IP reputation.
The system then assigns a risk score and displays a color-coded shield icon (green, yellow, or red) directly in the inbox list, providing an at-a-glance security overview.
Proactive URL Scanning: When an email is opened, all hyperlinks are automatically sent to the assessUrlRisk AI flow. The system then visually annotates each link with a security icon and a detailed tooltip explaining the risk, preventing clicks on malicious destinations.
AI-Assisted Safe Reply: After analyzing an email, the user can click "Generate Safe Reply." The aiAssistedReply flow considers the detected threats and the user's preferred tone (formal, neutral, casual) to draft a professional response that avoids disclosing sensitive information or engaging with a potential phisher.
AI Security Coach: A conversational AI chatbot, "Guardian," is available on the dashboard. Powered by the securityCoach flow, it can answer a wide range of cybersecurity questions, acting as an on-demand security expert for the user.
Full Email Client Functionality: The application includes all standard email features:
A dashboard with security analytics.
A fully interactive Inbox, Sent folder, and Bin.
Functionality to select, star, and delete emails.
A compose dialog to send new emails.
Customizable settings for AI sensitivity and reply tones.
The core methodology revolves around a layered, AI-driven analysis process orchestrated by Genkit.

Data Ingestion: The process begins when an email is received or viewed. Key data points are extracted: the sender's email/domain, the subject line, the full HTML body, and a list of all URLs.
Parallel AI Processing: This data is fed into specialized Genkit flows:
The detectPhishingEmailFlow receives the full email context. It uses a sophisticated prompt engineered to make the Gemini model act like a cybersecurity analyst. It evaluates the content against known phishing patterns and returns a structured JSON object containing a phishingScore, isPhishing boolean, a list of riskFactors, and a justification.
Simultaneously, the assessUrlRiskFlow takes each URL and instructs the AI to evaluate it based on its structure, domain reputation, and common obfuscation techniques, returning a riskScore and justification for each link.
Risk Aggregation and UI Synthesis: The front-end React components receive the structured JSON output from these AI flows.
For the inbox list, the phishingScore from the email analysis determines which shield icon to display.
Inside an email, the risk scores for each URL determine the icons placed next to the links. If the overall email risk is high, a prominent warning banner is also displayed.
User-Triggered AI Actions: When a user interacts with features like "Safe Reply" or the "Security Coach," a similar process occurs. The relevant context (the email content or the user's question) is sent to the appropriate AI flow (aiAssistedReplyFlow or securityCoachFlow), and the generated text response is displayed in the UI.
The application follows a modern, component-based architecture.

Frontend (Client-Side): Built with Next.js and React. The UI is composed of reusable components (e.g., Sidebar, Inbox, ComposeDialog). State management is handled by React Hooks (useState, useEffect) and shared across the app using React Context (EmailProvider, DashboardStateProvider) to ensure data consistency.
Backend Logic (Server Actions): All communication with the AI models is handled through Next.js Server Actions. These are secure functions that run on the server. The frontend calls these actions (e.g., analyzeEmailAction) to trigger the Genkit AI flows, ensuring that API keys and sensitive logic are never exposed to the client's browser.
AI Layer (Genkit Flows): This is the "brain" of the application, located in the src/ai/flows directory. Each flow is a self-contained module responsible for a specific AI task. It defines the expected input/output using zod schemas and contains the prompt that instructs the Gemini model on how to perform its analysis. This separation makes the AI logic modular, testable, and easy to update.
